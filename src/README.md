# 双语对照翻译（本地扩展）

在网页原文块的**下方追加译文**，原文保留不动。默认只在 Google 搜索页就位，
其他网站点一下按钮才注入。没有外部进程，不随系统或浏览器启动而常驻。

## 安装

1. Chrome 打开 `chrome://extensions/`
2. 右上角打开「开发者模式」
3. 点「加载已解压的扩展程序」，选择本目录（`src`）
4. 建议在扩展详情里把「键盘快捷键」设为 `Alt+T`（默认已建议）

项目总览、目录结构、如何跑测试见上一层的 `README.md`。

## 使用

- **Google 搜索页**：点工具栏图标 → 「翻译此页」。内容脚本已就位，点了立刻开始。
- **任意其他网站**：同样点图标，会自动注入脚本再翻译。
- **快捷键**：`Alt+T` 随时开关当前页面。
- 图标上的数字角标 = 当前页面已翻译的块数。

## 权限说明

| 权限 | 用途 |
|---|---|
| `storage` | 存设置和翻译缓存 |
| `activeTab` | 只在你点按钮的那一次，获得当前标签页的注入许可 |
| `scripting` | 点击按钮后向非 Google 页面注入脚本 |
| `host_permissions: translate.googleapis.com` | 发翻译请求（必须在后台发，内容脚本里发会被页面 CORS 拦） |
| `optional_host_permissions` | 只有你选「OpenAI 兼容接口」并填了地址时，才申请那一个域名的访问权 |

没有请求 `<all_urls>` 的常驻权限，也没有任何本地服务或外部进程。

## 翻译引擎

引擎都在 `providers.js` 里，加一个新引擎就是往 `PROVIDERS` 数组里加一项：
`build(text, tl, cfg)` 返回 `{url, init}`，`parse(json)` 返回译文或 `null`。
`null` 一律按失败处理，所以解析不确定时宁可返回 `null`，也不要吐出可疑文本。

| id | 引擎 | 需要的凭证字段 |
|---|---|---|
| `mymemory` | MyMemory（默认） | `email`（可选） |
| `baidu` | 百度翻译开放平台 | `appid`, `key` |
| `caiyun` | 彩云小译 | `token` |
| `deepl` | DeepL API | `key` |
| `openai` | OpenAI 兼容接口 | `base`, `key`, `model` |
| `google` | Google 翻译（三个域名轮换） | 无 |

`openai` 额外实现了 `buildBatch` / `parseBatch`：一次请求翻多段（默认上限 10 段 / 3000 字符），
`background.js` 会把 120ms 内到达的请求合并成一批。批量返回做严格校验（数量、id、非空缺一不可），
不合格就自动退回逐条，不会把模型的胡话贴到页面上。

测试：`npm run test:providers`（含 MD5 签名与 Node crypto 对齐、各引擎请求形状与解析）。

## 选块与渲染的实现要点

- **元素级单元**：块级、可见、值得翻，且后代里没有更细的块或不可翻区域（`code`/`pre`/按钮等）
- **行内片段**：块级容器里被块级子元素隔开的连续行内内容，连同 `inline-block` 里的文字一起收集。
  只按块级元素取块会整段漏掉这类裸文本——Wikipedia、Nexus Mods 这类站点正是重灾区
- **插入位置按父元素布局决定**：普通流式布局插兄弟节点；`flex`/`grid` 容器、表格行、列表、下拉
  改为插到元素内部末尾（插兄弟会多出一个 flex 子项把布局撑开，在表格行/列表里更是非法结构）
- **悬停模式**：不插入节点，只记录译文并在 `mouseover` 时弹出气泡

### 什么内容走悬停（`decideMode`）

按语义判断，不是只按长短：

| 判定 | 依据 | 结果 |
|---|---|---|
| 外围区域 | `nav/header/footer/aside`、`role=navigation` 等，或类名/ID 含 `tag/category/label/meta/byline/nav/menu/sidebar/toolbar/...` | 悬停（但成句的长段落仍直接显示，悬停读不了长文） |
| 标题正文 | `h1`–`h6`、`itemprop=articleBody`、类名含 `content/body/post/article/description/...`、`p/li/td` 里的成句长文本 | 直接显示 |
| 都没命中 | 回退到长度规则（≤ `hoverBelow`，默认 30） | 悬停 |

外围容器里有多个行内子项（导航、标签列表）时会下沉成逐项处理，
这样悬停一个标签只出这一个标签的译文，而不是整条列表揉成一句。

### 用户名 / 作者名（`isUserNameish`）

三层信号：结构化标注（`rel=author`、`itemprop=author/creator`、`data-author*`、`<address>`）、
文本形态（`@handle`、"by xxx"、"作者：xxx"、像名字的短文本）、
链接指向（`/user/ /u/ /member/ /profile/ /author/ ...`）。
后两类只在该元素文本"像名字"（≤40 字符、≤4 个词、无句末标点）时才生效，
否则作者简介这类长文本会被误判跳过。
块里混着用户名时整块下沉逐段处理，好把名字排掉、同时不留下"Posted by"这种碎片。

弹窗里的「跳过用户名 / 作者名」可整体关闭（`skipNames`）。

## 关键参数（都在 `content.js` 顶部）

| 参数 | 默认 | 含义 |
|---|---|---|
| `MIN_LEN` | 8 | 短于此长度不翻 |
| `CONCURRENCY` | 5 | 并发请求数，被限流就降到 2–3 |
| `LATIN_RATIO` | 0.3 | 原文英文占比高于此值才翻，用来跳过已有中文的内容 |
| `SCAN_DEBOUNCE` | 300 | 动态内容重扫的防抖毫秒数 |

## 已知限制

- 用 Google 免费端点 `translate_a/single`，非官方接口，偶发限流。请求失败只是少翻几块，下次访问会命中缓存。
- 若状态显示「翻译失败 N 次」，点弹窗里的「诊断连接」，它会真的打一次网络并逐个端点报告
  HTTP 状态、耗时和错误原因。三个端点都失败就是网络/代理问题。

- `flex` / `grid` 布局里的块，译文位置可能不理想，靠 `content.css` 里的 `.bt-trans` 规则微调。
- 行内元素（`<a>`、`<em>`、`<span>`）不会被单独当作翻译单元，它们随所在的块级父元素一起翻。
- 翻不到的只剩「块级容器里直接写着裸文本、且同级还有块级子元素」这种结构，Google 搜索页不存在这种情况。
- 只翻 `document` 主框架（`all_frames: false`），跨域 iframe 内容不动。
- 「只看译文」会隐藏原文块，个别布局会因此塌陷，切回即可。
- 没有图标文件，Chrome 会用默认图标；要自定义就加 `icons/` 并在 manifest 里声明。

## 提速原理

单个请求 200–500ms 改不了，感知速度靠四点：

1. 视口内的块优先排队，首屏译文约 300–600ms 出现
2. 谁先返回先渲染，不等整批
3. 相同文本合并成一次请求（搜索页重复短语很多）
4. 后台带持久化缓存，第二次访问基本零延迟
